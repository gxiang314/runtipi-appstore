# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

The official Runtipi App Store: ~275 self-hosted app definitions under `apps/`, each a Docker Compose bundle plus metadata consumed by [Runtipi](https://github.com/runtipi/runtipi). **No new apps are accepted** — PRs should be limited to bug fixes and version updates.

## Commands

Uses **bun** as the runtime and test runner.

- `bun install` — install dependencies
- `bun run test` — full test suite: `bun test` (validates every app in `apps/`) plus `bun run scripts/validate-json.js` (validates all `docker-compose.json` files against the remote schema at schemas.runtipi.io; needs network)
- `bun test apps/__tests__/apps.test.ts` — just the app config tests
- `bun run lint` — Biome check; `npx @biomejs/biome check --write` to auto-fix
- `bun run test:codemod:native-docker` — codemod tests
- `bun run commit` — commitizen-guided commit (conventional commits enforced by commitlint; lefthook pre-commit runs Biome + tests)

## App structure

Each app lives in `apps/<id>/`:

- `config.json` — app manifest (schema: `apps/app-info-schema.json`). Key fields: `id` (must equal directory name), `port` (unique across all apps — tests enforce this), `version` (upstream version), `tipi_version` (integer, bump by 1 on *every* change to the app), `updated_at` (epoch ms), `dynamic_config`, `supported_architectures`.
- `docker-compose.yml` — the newer "native docker" format. Runtipi-specific settings live in `x-runtipi` extension blocks: per-service (`internal_port`, `is_main`) and top-level (`schema_version: 2`). Uses env vars injected by Runtipi: `${APP_DATA_DIR}`, `${APP_DOMAIN}`, `${APP_PROTOCOL}`, plus vars declared in `config.json`'s `form_fields`.
- `docker-compose.json` — legacy "dynamic compose" format; still present in many apps and validated against the remote schema. The `codemods/native-docker` package converts json → yml (`npx codemod@latest @runtipi/native-docker`, dry-run by default).
- `metadata/description.md` and `metadata/logo.jpg` — both required by tests.

## Updating an app version (the most common change)

`scripts/update-config.ts` does this automatically and is what Renovate runs as a post-upgrade task:

```bash
bun ./scripts/update-config.ts apps/<id>/docker-compose.yml <newVersion> <imageName>
```

It rewrites the image tag in both compose files, sets `config.version` if the image is the main service, bumps `tipi_version`, and refreshes `updated_at`. When editing manually, replicate all of those steps — image tag(s), `version`, `tipi_version` +1, `updated_at`.

Renovate (see `renovate.json`) auto-opens these PRs by regex-matching `image:` lines in compose files; database images (postgres, mariadb, redis, etc.) are intentionally pinned and excluded.

## Other notes

- `apps/__tests__/apps.test.ts` iterates over every app with `available: true` and enforces the invariants above (unique ports/ids, required files, parsable compose json via `@runtipi/common`). Run it after any app change.
- The README app table is generated by CI (`readme-generator.yml`) from `templates/README.md` — edit the template, not the README table.
